# Stack

## Продукт
CRM для магазинів одягу. Тенант — окрема компанія-клієнт, дані якої повністю ізольовані від інших тенантів (жодного перетину на рівні БД).

Масштаб: орієнтовно 1000 тенантів, до ~20 користувачів на тенант.

## Технічний стек

| Шар | Вибір |
|---|---|
| Мова | TypeScript |
| Фреймворк | Next.js (App Router) — фронт + бек в одному проєкті |
| БД | PostgreSQL |
| Data-access | Drizzle ORM через єдиний тенант-скоупований шар (розділ 6 CLAUDE.md) + PostgreSQL Row-Level Security як другий рубіж захисту |
| UI | Tailwind CSS + shadcn/ui |
| Auth | Email + пароль (сесії на сервері). Заплановано: Google OAuth (пізніше, не зараз) |
| Хостинг зараз | Docker Compose (локально) |
| Хостинг далі | VPS (бюджетний, без конкретного провайдера поки) |

## Тенант і мультитенантність
- Тенант = компанія-клієнт (магазин одягу або мережа).
- Кожна прикладна таблиця має `tenant_id` (розділ 6 CLAUDE.md — тверді правила, без винятків без запису в `db.md`).
- `tenant_id` береться тільки з серверної сесії, ніколи з клієнта.

## Ролі
- **Власник (owner)** — повний доступ. Єдина активна роль на старті.
- **Менеджер (manager)** — заплановано, права ще не визначені.
- **Продавець (seller)** — заплановано, права ще не визначені.
- **Суперадмін** — окремий явний шлях (розробник/підтримка), з логуванням, поза звичайним тенант-скоупом.

## Межі проєкту (поточний етап)
Не робимо: мобільний застосунок (буде окремим проєктом), інтеграції з маркетплейсами, бухгалтерський модуль, розмежування прав manager/seller.
Дедлайнів немає. Бюджет хостингу — мінімальний/бюджетний VPS.
