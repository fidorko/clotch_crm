# UI Kit

Базові компоненти — shadcn/ui (`src/components/ui/`), обгортка над Base UI. Композиція тригерів — через проп `render`, не `asChild` (це API з Radix, тут не працює і ламає гідрацію).

## Правило: `HeaderActions` — на КОЖНІЙ сторінці

За прямою вказівкою людини: будь-яка сторінка/екран (список, картка, форма створення/редагування) має в шапці рядок хлібних крихт з `<HeaderActions />` праворуч (`layout/HeaderActions.tsx`) — той самий каркас, що `ProductHeader`/`ProductsHeader`/`SettingsHeader`/`SuppliersHeader`/`SupplierForm`/`CategoryForm`. Це стосується й довідників «Довідники» (`/settings/references/*`, включно з kind-сторінками) — не лише «великих» екранів. Нова сторінка без цього рядка — недороблена, перевіряй одразу при верстці нового модуля, не чекай окремого зауваження.

## Правило: рідко змінюваний текст — «перегляд + олівчик», не always-open поле

За прямою вказівкою людини: якщо поле — це **окремий підпис/заголовок/значення**, яке зазвичай тільки читають і зрідка редагують (назва в картці-заголовку, поле форми, значення довідника показане один раз на екрані) — за замовчуванням просто текст, редагування відкривається кліком на олівчик (`Pencil`, `lucide-react`), закривається на blur/Enter (Escape — скасовує без збереження). Готові компоненти — `EditableTextRow`/`EditableNumberRow`/`EditableSelectRow`/`PriceModeRow` (нижче) і `CategoryTreeSelect` (`defaultOpen`+`onOpenChange`); зразок — `ProductInfoPanel`.

**Виняток, свідомий, не порушення правила:** компактні списки з швидким масовим редагуванням багатьох однотипних рядків поспіль (`ColorsList`, `MaterialsManager`, `CareInstructionsList`, `SizesList` — там усе поле завжди відкрите, зберігається по blur/Enter, без олівчика) — там мета інша: редагувати десятки рядків підряд, а не одне значення в контексті картки. Не переносити ці списки на «олівчик»-патерн без окремої вказівки — так вирішили свідомо (`decisions.md`).

| Combobox | ui/combobox.tsx | `Select` із пошуком по вводу (`@base-ui/react/combobox`): `ComboboxInputGroup` (`ComboboxInput` + `ComboboxTrigger`) + `ComboboxContent` (`ComboboxItem`, вбудований `Empty` — «Нічого не знайдено»). `items` на `Combobox` — повний список, фільтрація вбудована. Той самий стиль полів/попапу, що й `Select`. **Групування** (додано для `FabricTypePossibleMaterialsField`): `items` — масив груп `{label, items: id[]}`, `ComboboxContent` рендерить групу через render-prop `(group) => <ComboboxGroup items={group.items}><ComboboxGroupLabel/><ComboboxCollection>{(id) => <ComboboxItem/>}</ComboboxCollection></ComboboxGroup>` — для плоского списку `ComboboxCollection` не потрібен, `ComboboxList`(=`ComboboxContent`) сама огортає функцію-children. `multiple` + масив у `value`/`onValueChange` — мультиселект. Інлайн-створення нового елемента — синтетичний `value` (напр. `"__create__"`), перехоплюється в `onValueChange` до виклику `onSelectedIdsChange`. `ComboboxGroupLabel` стилізовано `text-primary`/`text-sm font-semibold` (не приглушений сірий, як `DropdownMenuLabel`) — за прямою вказівкою, категорія має виділятись; пункти групи — `pl-4` (замість базового `pl-1.5` `ComboboxItem`, через `className`, `cn`/`tailwind-merge` коректно перебиває) — відступ зліва під групою |

| PriceModeRow | ui/price-mode-row.tsx | той самий патерн «перегляд + олівчик → редагування», що `EditableNumberRow`, але з перемикачем Грн/%: до кліку — просто ціна. Після кліку на олівчик — перемикач Грн/% зʼявляється завжди; у режимі «Грн» ліва позиція (де в перегляді була ціна) стає редагованим числовим полем; у режимі «%» ліва позиція лишається розрахованою ціною (не редагована напряму), а поле вводу відсотка зʼявляється праворуч від перемикача. І сума (`Math.round`, не `toFixed(2)` — раніше показувало копійки/нецілі значення від розрахунку з відсотка, за зауваженням виправлено), і відсоток (`Math.round` при кожній зміні, `step={1}`) — завжди цілі числа. Формула розрахунку — пропом `computeFromPercent`, компонент не знає базу. Опційний проп `warning` — червоний текст під рядком. Цінова політика `ProductInfoPanel`, 4 використання |

| EditableTextRow | ui/editable-text-row.tsx | той самий патерн «перегляд + олівчик → редагування», для вільного тексту (не довідника-списку). `label` опційний — з ним рядок «лейбл (`w-40`) — значення», без нього просто «значення + олівчик» (заголовок картки, не поле форми) — так використано в `TypeGroupCard` (`TypeValuesEditor`, «Розміри та заміри», назва типу) |
