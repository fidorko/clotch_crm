# UI Kit

Базові компоненти — shadcn/ui (`src/components/ui/`), обгортка над Base UI. Композиція тригерів — через проп `render`, не `asChild` (це API з Radix, тут не працює і ламає гідрацію).

## Правило: `HeaderActions` — на КОЖНІЙ сторінці

За прямою вказівкою людини: будь-яка сторінка/екран (список, картка, форма створення/редагування) має в шапці рядок хлібних крихт з `<HeaderActions />` праворуч (`layout/HeaderActions.tsx`) — той самий каркас, що `ProductHeader`/`ProductsHeader`/`SettingsHeader`/`SuppliersHeader`/`SupplierForm`/`CategoryForm`. Це стосується й довідників «Довідники» (`/settings/references/*`, включно з kind-сторінками) — не лише «великих» екранів. Нова сторінка без цього рядка — недороблена, перевіряй одразу при верстці нового модуля, не чекай окремого зауваження.

## Правило: рідко змінюваний текст — «перегляд + олівчик», не always-open поле

За прямою вказівкою людини: якщо поле — це **окремий підпис/заголовок/значення**, яке зазвичай тільки читають і зрідка редагують (назва в картці-заголовку, поле форми, значення довідника показане один раз на екрані) — за замовчуванням просто текст, редагування відкривається кліком на олівчик (`Pencil`, `lucide-react`), закривається на blur/Enter (Escape — скасовує без збереження). Готові компоненти — `EditableTextRow`/`EditableNumberRow`/`EditableSelectRow`/`PriceModeRow` (нижче) і `CategoryTreeSelect` (`defaultOpen`+`onOpenChange`); зразок — `ProductInfoPanel`.

**Виняток, свідомий, не порушення правила:** компактні списки з швидким масовим редагуванням багатьох однотипних рядків поспіль (`ColorsList`, `MaterialsManager`, `CareInstructionsList`, `SizesList` — там усе поле завжди відкрите, зберігається по blur/Enter, без олівчика) — там мета інша: редагувати десятки рядків підряд, а не одне значення в контексті картки. Не переносити ці списки на «олівчик»-патерн без окремої вказівки — так вирішили свідомо (`decisions.md`).

## Правило: висота панелей у багатоколонковому гріді — два варіанти, свідомий вибір

**За замовчуванням — без `h-full`.** Картка з `h-full` у гріді `grid-cols-[Xfr_Yfr]` розтягується під висоту найвищої сусідки, тож щойно в одній панелі зʼявляється більше значень — поруч виникає порожнеча. Спосіб — `items-start` на гріді, кожна колонка — самостійний вертикальний стек (`flex flex-col gap-4`), картки по своїй висоті.

**Коли людина явно просить однакову висоту (орієнтир — найбільший елемент)** — протилежний спосіб: без `items-start` (типова поведінка CSS-грід — `stretch`, комірка розтягується під найвищий контент рядка) + `h-full` на кожній картці/обгортці-колонці, щоб вона видимо заповнила розтягнуту комірку. Коротші колонки лишають порожнє місце знизу — це очікувано, не баг. Зразок — обидва ряди `ProductGeneralTab` (2026-08-03, п'ятий прохід — пряма вказівка «мають мати однакову висоту» для ряду 1 Фото/Основне/Характеристики, тоді окремим уточненням і для ряду 2 — «висота SKUDetail повинна = висоті ProductSkuSection»).

Не змішувати без потреби: перший варіант — типовий default для випадкових сусідніх блоків, другий — коли людина явно просить вирівняти.

**Гочта з `DevBlockLabel`:** коли `dev=true` (`lib/dev/dev-flags.ts`), він вставляє свій `<div>` між стретчнутою грід-коміркою і карткою — без `h-full` на самому цьому div відсоткова висота картки просто ігнорується (CSS-правило: `height: %` не працює, якщо в батька `height: auto`). `DevBlockLabel` підтримує опційний проп **`stretch`** саме для цього (за замовчуванням `false`) — вмикати лише на тих використаннях, де компонент справді сидить у стретчнутій грід-комірці (усі 5 у `ProductGeneralTab`: `ProductPhotoGallery`/`ProductInfoPanel`/`ProductCharacteristicsPanel`/`ProductSkuSection`/`SKUDetail`). **`h-full` без розбору на кожному використанні — баг, не фікс:** спершу так і було (2026-08-03, перший прохід), і на сторінках, де `DevBlockLabel` огортає елемент у flex-column (напр. `SettingsHeader` + контент нижче, `settings/page.tsx`) — `h-full` на заголовку конкурував з сусіднім flex-item за висоту й роздував порожню обгортку, зіштовхуючи решту вниз (ловили на `WarehousesTab`, той самий день, коли додавали склади). Виправлено проп-ом `stretch` — типове використання (список/форма/заголовок, не в стретчнутій грід-комірці) лишає `h-full` вимкненим.
