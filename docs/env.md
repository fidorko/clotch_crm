# Env

## Запуск (розробка)
1. `docker compose up -d` — підняти PostgreSQL локально (перший раз і після перезавантаження машини).
2. `npm run dev` — Next.js dev-сервер.

**Один порт.** Застосунок завжди піднімається на одному й тому самому порту (3000 за замовчуванням). Якщо запуск не вдався або потрібен перезапуск — спершу зупинити наявний процес, потім запускати знову. Не плодити паралельні процеси на різних портах.

**Один Postgres-контейнер.** `docker compose up -d` — ідемпотентно, повторний виклик не створює дублікат.

## Змінні оточення
Скопіювати `.env.example` → `.env` (не комітиться). Значення для локальної розробки — підставні, реальні секрети сюди ніколи не пишуться.

| Змінна | Призначення |
|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` | `docker-compose.yml` — локальний контейнер Postgres |
| `DATABASE_URL` | Власник схеми — міграції (`drizzle-kit`), сід. Обходить RLS. |
| `APP_DATABASE_URL` | Non-owner роль `app_user` — запити застосунку (`src/server/db/client.ts`). RLS діє. |
| `DEV_TENANT_ID` | `TODO(auth)` — тимчасовий tenantId, доки нема сесій. Див. `db.md`. |

## Перше підключення БД (одноразово на машину)
```
docker compose up -d
npm run db:generate   # тільки якщо схема змінилась і міграції ще нема
npm run db:migrate
npm run db:setup-role
npm run db:seed
```
Деталі схеми, RLS та мультитенантності — `docs/db.md`.
