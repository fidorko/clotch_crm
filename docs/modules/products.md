# Модуль: products

**Статус:** UI `в роботі` · Логіка `—` · Бек `в роботі` · БД `в роботі`
**Маршрут:** /products, /products/[id]
**Оновлено:** 2026-07-30 (список товарів /products; картка товару — збереження всієї форми одним запитом, «Створити товар»/«Редагувати»)

## Призначення
Список товарів (пошук/фільтри/пагінація/видалення, за мотивами референсного скріншоту, у власному стилі) і картка товару: загальна інформація, фото, варіанти SKU (колір × розмір), залишки, статистика по товару. За зразком `Image.png`.

## Дані
Сторінка `/products` (список) читає `listProducts(tenantId, filters)` — фільтри/пагінація йдуть через `searchParams` URL (`q`/`category`/`status`/`stock`/`page`), сторінка серверна, `ProductsTable` — клієнтський контролер фільтрів, що навігує на нову URL (`router.push`). «Додати товар» створює рядок у `products` мінімальними NOT NULL-плейсхолдерами й `is_draft = true`, одразу веде на `/products/[id]`.
На картці товару вся форма (ім'я/статус/категорія/колекція/характеристики/ціни/метадані/теги) тепер зберігається одним запитом через `saveProductAction` → `saveProduct` (`server/data/products.ts`) — оновлює рядок `products` і синхронізує `product_tags` (знайти-або-створити тег за міткою, tenant-скоуповано, повна заміна набору тегів товару), знімає `is_draft`. `product.season`/`product.brand` — і далі read-only (у формі нема полів для їх редагування, як і раніше).
Сторінка `/products/[id]` читає реальні дані з PostgreSQL через `getProductById(tenantId, id)` (`src/server/data/products.ts`) — таблиці `products`, `product_skus`, `product_photos`, `product_measurements`, `tags`/`product_tags` (детально — `db.md`). `tenantId` поки з dev-константи (`TODO(auth)`, `db.md`). Мок `src/lib/mocks/products.ts` лишається як джерело сіду (`npm run db:seed`), UI-код на нього більше не посилається (крім `selectedSku` — див. «Відкрито»).
`page.tsx` також тягне `listCategories(tenantId)` (`server/data/categories.ts`, той самий шар, що й у `settings`) і пробрасовує в `ProductGeneralTab` → `ProductInfoPanel` для ієрархічного піклера категорії.
Розмірна сітка (`ProductSizeChart.tsx`) — окремо захардкоджена, не прив'язана до товару/категорії. Типи замірів — тимчасовий довідник `lib/constants/measurement-types.ts` (`imageUrl` завжди порожній), розміри SKU-матриці — `lib/constants/sku-variant-options.ts`; обидва свідомо не нормалізовані в БД цього проходу (обґрунтування — `db.md`). Кольори SKU-матриці й поля «Колір» — вже з БД (`server/data/colors.ts`, `listColors(tenantId)` у `page.tsx`, settings → «Довідники» → «Кольори»), `product_skus.color`/`color_hex` лишаються копією значення на момент створення SKU (не FK).
