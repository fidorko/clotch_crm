# Модуль: settings — піддокумент «Довідники» (settings → Довідники)

Частина модуля `settings` (`docs/modules/settings.md`) — винесено окремо, бо основний файл модуля впритул до ліміту (`CLAUDE.md`, розділ 0; правило — `docs/_module-template.md`). Статус/доступ/зв'язки — спільні з `settings.md`, тут немає власного запису в `map.md`.

**Маршрут:** /settings?tab=references, /settings/references/currencies, /settings/references/suppliers(+/[id]/+/new), /settings/references/[kind] (3 «просто назва» довідники)

## Призначення
Розділ «Довідники» (`ReferencesList.tsx`) — дві групи: **«Характеристики товару»** (описують сам виріб: Кольори/Тип тканини/Матеріали/Інструкція по догляду/Розміри/Заміри — усі плитка+попап без власної сторінки, + довільна кількість користувацьких характеристик) і **«Системні»** (Виробники/Постачальники/Країни/Валюти/Одиниці виміру — без можливості видалити весь довідник). Кожна плитка групи «Характеристики товару» має 3 перемикачі (CRM/вітрина/фільтри) — `reference_dictionary_flags` (для `custom_characteristics` — власні boolean-колонки).

**2026-08-02, за прямою вказівкою людини — розділено два раніше об'єднані довідники:** «Розміри та заміри» → окремі плитки «Розміри»/«Заміри»; «Тип тканини та матеріал» → окремі плитки «Тип тканини»/«Матеріали» (раніше «Матеріали» була згорнутою секцією всередині попапу типу тканини). Деталі — «Зроблено» нижче.

## Дані
Усі — тенант-скоуповано, RLS: «Кольори» (`colors`), «Валюти» (`currencies`), «Постачальники» (`suppliers`+3 дочірні), «Характеристики» (`custom_characteristics`+`custom_characteristic_values`), «Тип тканини»/«Матеріали» (`fabric_types`+`fabric_type_possible_materials`+`materials` — дві незалежні таблиці, `materials` більше не підпорядкована `fabric_types` на рівні UI, лише через `fabric_type_possible_materials`), «Інструкція по догляду» (`care_instructions`), «Розміри»/«Заміри» (`size_types`+`size_values`, `measurement_types`+`measurement_values` — завжди були 2 незалежні таблиці, тепер і в UI 2 незалежні плитки), «Прапорці довідників поза `custom_characteristics`» (`reference_dictionary_flags`, вільний текстовий `dictionary_key`). Деталі схеми — `db.md`.

## Зроблено
- 2026-08-02 — довідник «Тип тканини» засіяно 21 реальним типом (Футер двонитка/трьохнитка, Кулірна гладь, Інтерлок, Рибана, Піке, Джерсі, Денім, Твід, Шифон, Атлас, Сатин, Поплін, Бязь, Фланель, Вельвет, Букле пальтове, Льняне полотно, Шовк натуральний, Оксфорд, Софтшелл) — за прямим проханням людини «пошукати в інтернеті й заповнити всі поля форми». Дані (щільність/розтяжність/лицьова-тильна сторона/тактильні відчуття/можливі матеріали) зведено з галузевих статей про склад і переплетення тканин (`lib/mocks/fabric-types.ts`, `db:seed`); де достовірне значення не знайшлось або одиниці виміру джерела не збігались з полем (`density`, г/м²) — поле лишено `null` (Інтерлок/Рибана/Піке/Джерсі/Льняне полотно/Оксфорд), за прямою вказівкою «не вигадуй, лишай пустим». Жоден новий матеріал у довідник додавати не довелось — усі знайдені в дослідженні матеріали складу вже були серед 55 засіяних раніше. `code` (унікальний slug) генерується тим самим транслітератором, що `server/data/fabric-types.ts` (невеликий дубль у `seed.ts` — сід ставить фіксовані назви одноразово, ретрай при колізії там не потрібен, на відміну від людського вводу через форму).

Свідомо не миттєве створення: два швидкі кліки «Додати» до вводу назви конфліктували б на `UNIQUE(tenant_id, name)` з порожнім рядком. `ColorsList` не тримає локального масиву (рендерить `colors`-проп напряму, оновлюється через `router.refresh()`) — на відміну від `MaterialsManager`, драфт-рядок там не потребує окремої синхронізації зі станом попапу-батька.
