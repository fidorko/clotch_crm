# Модуль: settings — піддокумент «Постачальники»

Частина модуля `settings` (`docs/modules/settings.md`) — винесено окремо, бо основний файл модуля переріс ліміт (`CLAUDE.md`, розділ 0; правило — `docs/_module-template.md`). Статус/доступ/зв'язки — спільні з `settings.md`, тут немає власного запису в `map.md`.

**Маршрут:** /settings/references/suppliers, /settings/references/suppliers/new, /settings/references/suppliers/[id]

## Файли
| Шлях | Роль |
|---|---|
| src/app/settings/references/suppliers/page.tsx | список постачальників — тягне `listSuppliersWithPrimaryContact(tenantId)`, рендерить `SuppliersHeader` + `SuppliersList` |
| src/app/settings/references/suppliers/new/page.tsx, [id]/page.tsx | Server Components — `new` рендерить `SupplierForm` без даних, `[id]` тягне `getSupplierById` (`notFound()`, якщо нема під цим тенантом); заголовок/хлібні крихти — усередині `SupplierForm`, не в `page.tsx` (кнопка «Зберегти» прив'язана до стану форми) |

Іконка «Фільтри» зі зразка-скріна не додана — не мала визначеної поведінки (жодних додаткових фільтрів понад пошук/тип/статус ще не потрібно) |

## Зроблено
- 2026-07-31 — список постачальників (`SuppliersList`) перероблений за зразком-скріном людини: рядок фільтрів (пошук за назвою/кодом/контактом + `Select` тип + `Select` статус, усі клієнтські, без запиту на сервер), таблиця замість карток-рядків — аватар-ініціали в кольоровому колі (2 літери, колір по хешу id), бейдж типу з іконкою, контакт (перша контактна особа), статус кольоровою крапкою, дата+час оновлення, дії — **олівець (редагувати) + кошик (видалити)**, за прямою вказівкою, замість попереднього «клік на назву → редагування». Новий `listSuppliersWithPrimaryContact` (`server/data/suppliers.ts`) — той самий список постачальників + перша контактна особа кожного одним батч-запитом по `supplierContacts` (не в циклі). Заголовок (`SuppliersHeader`) — лічильник тепер кругла пігулка (`Badge`) біля назви, додано підпис «Керуйте постачальниками...». Перевірено: рендер сторінки, і окремо — постачальник із реальним контактом (ім'я/телефон/email відображаються в колонці «Контакт»)
- 2026-07-30 — довідник «Постачальники»: другий раунд правок за зауваженням («2 колонки», «різна ширина інпутів», «не зробив підказки»). (1) «Основна інформація» — `grid-cols-2` замість одноколонкового стеку; (2) «Адреса» перенесена в «Контактна інформація» (`grid-cols-3`: країна/місто/адреса — поле «Індекс» прибрано взагалі, разом з колонкою `postal_code` у БД, міграція `0009`); (3) «Месенджери»/«Соцмережі» винесено в окрему картку, поряд у `grid-cols-2` (раніше — одне під одним усередині «Контактної інформації»); (4) `SupplierContactsFields` — кошик видалення переїхав із рядка полів у шапку блоку («Контактна особа N»), усі 4 поля контакту тепер в єдиному `grid-cols-2` (раніше рядок телефон/email без кнопки поруч мав іншу ширину, ніж рядок ім'я/посада з кнопкою — «сходинка»); (5) картка «Підказка» отримала намальовану SVG-ілюстрацію (`SupplierHintIllustration`) замість голої іконки — за зразком-скріном людини
- 2026-07-30 — довідник «Постачальники» (`/settings/references/suppliers`) допрацьовано за зауваженням («не схоже на зображення яке я надавав» + «іконки повинні бути фірмовими»): (1) заголовок форми/списку тепер той самий каркас, що `ProductsHeader` — клікабельні крихти + `HeaderActions` зверху, назва/лічильник/дії в другому рядку (раніше — голий `h1` без цього каркасу); кнопка «Зберегти» — зовні `<form>`, зв'язана `form="supplier-form"`; (2) іконка в кольоровому колі перед заголовком кожної картки (`SectionTitle`) і префікс-іконки в полях Веб-сайт/Телефон/Email (`SupplierIconInput`) — той самий візуальний патерн, що плитки `ReferencesList`/пошук `CategoriesTab`; (3) іконки месенджерів/соцмереж замінено з 2-літерних кольорових бейджів на справжні фірмові лого — додано `react-icons` (`fa6`), погоджено з людиною через питання (`decisions.md`, правило 9.9 CLAUDE.md)
