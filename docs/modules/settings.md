# Модуль: settings

**Статус:** UI `в роботі` · Логіка `—` · Бек `в роботі` · БД `в роботі`
**Маршрут:** /settings?tab=..., /settings/categories/new, /settings/categories/[id], /settings/references/currencies, /settings/references/suppliers, /settings/references/suppliers/new, /settings/references/suppliers/[id], /settings/references/[kind] (4 «просто назва» довідники)
**Оновлено:** 2026-07-31 (3 перемикачі — на всіх плитках «Характеристики товару», включно з не-`custom_characteristics`; «Кольори» перенесено з окремої сторінки в попап; курсор `pointer` уніфіковано на всіх клікабельних плитках)

## Призначення
Сторінка налаштувань магазину: розділи (вітрина, загальні, категорії товару, замовлення, довідники, склади, доставка, оплата, тарифний план) — вибираються через підменю сайдбару (розгортається інлайн під «Налаштування», решта пунктів сайдбару лишається видимою), розділ у URL як `?tab=`. «Категорії товару» — повний CRUD з реальною БД (список/створення/редагування/видалення, ієрархія, зображення). «Довідники» — дві групи, за прямою вказівкою: **«Характеристики товару»** (5 стандартних пунктів: Тип тканини, Інструкція по догляду, Розміри та заміри, Кольори + довільна кількість користувацьких характеристик — Колекції/Сезон/Бренди/Теги/Посадка вже серед них, кожна створюється/редагується/видаляється через один попап, «+Додати довідник») і **«Системні»** (5 пунктів: Виробники, Постачальники, Країни, Валюти, Одиниці виміру — без можливості видалити весь довідник). Лише «Інструкція по догляду» й «Розміри та заміри» ще без бекенду (інша форма даних, не просто назва).

## Використовує з ui-kit

## Дані
«Категорії товару» — таблиця `categories` у PostgreSQL (повний CRUD через `server/data/categories.ts` + Server Actions), тенант-скоуповано, RLS. `products.category_id` (FK на `categories.id`, `ON DELETE SET NULL`) — реальний зв'язок товару з категорією, звідки рахується «Товарів» у списку. Довідники — статичний масив у `ReferencesList.tsx` (8 пунктів у двох групах: 3 «Характеристики товару» + 5 «Системні», `group`-поле) + «Кольори» окремою плиткою + довільна кількість `custom_characteristics`; «Кольори» (`colors`), «Валюти» (`currencies`), «Постачальники» (`suppliers`+3 дочірні), «Характеристики» (`custom_characteristics`+`custom_characteristic_values`) і «Прапорці довідників поза custom_characteristics» (`reference_dictionary_flags`) — з реальною БД, тенант-скоуповано, RLS; `page.tsx` тягне `listColors`/`listCurrencies`/`listSuppliers`/`listCustomCharacteristicsWithValues`/`listDictionaryFlags` і пробрасовує пропами в `ReferencesList` для лічильника й прев'ю значень. Деталі схеми — `db.md`.
Картка товару (`/products/[id]`) тепер читає `listColors(tenantId)` і пробрасовує в `ProductGeneralTab` → `ProductInfoPanel` (поле «Колір» без варіацій) та `ProductSkuSection` → `ProductSkuTable` (конструктор SKU-матриці, дропдаун «+Колір») — раніше обидва брали хардкод `COLOR_OPTIONS` з `lib/constants/sku-variant-options.ts` (тепер видалено, лишився тільки тип `ColorOption`).
Теги товару (`ProductMetaPanel` → `TagsSection`) — і далі та сама таблиця `product_tags`, лише `characteristic_value_id` замість колишнього `tag_id`; `syncProductTags` (`server/data/products.ts`) знаходить/створює характеристику «Теги» тенанта за `system_key="tags"` (не за назвою). UI картки товару не змінився — лише джерело в БД, `db.md`.

**Нюанс Select з ui-kit:** якщо `value` опції не збігається з людським лейблом (напр. `"all"`/`"active"`, а не сам текст), `SelectValue` треба явно дати render-функцію (`<SelectValue>{(value) => label}</SelectValue>`) — інакше показує сирий `value`. У `CategorySelectRow` (`ProductInfoPanel`) цього не було видно, бо там `value` і лейбл — той самий рядок.
