# Модуль: settings

**Статус:** UI `в роботі` · Логіка `—` · Бек `в роботі` · БД `в роботі`
**Маршрут:** /settings?tab=..., /settings/categories/new, /settings/categories/[id], /settings/references/currencies, /settings/references/suppliers, /settings/references/suppliers/new, /settings/references/suppliers/[id], /settings/references/[kind] (3 «просто назва» довідники)
**Оновлено:** 2026-08-01 (довідники «Інструкція по догляду» й «Розміри та заміри» підключено до БД — плитка+попап, той самий патерн, що «Кольори»)

## Призначення
Сторінка налаштувань магазину: розділи (вітрина, загальні, категорії товару, замовлення, довідники, склади, доставка, оплата, тарифний план) — вибираються через підменю сайдбару (розгортається інлайн під «Налаштування», решта пунктів сайдбару лишається видимою), розділ у URL як `?tab=`. «Категорії товару» — повний CRUD з реальною БД (список/створення/редагування/видалення, ієрархія, зображення). «Довідники» — дві групи, за прямою вказівкою: **«Характеристики товару»** (Тип тканини та матеріал/Інструкція по догляду/Розміри та заміри/Кольори — усі плитка+попап без власної сторінки, + довільна кількість користувацьких характеристик — Колекції/Сезон/Бренди/Теги/Посадка вже серед них, кожна створюється/редагується/видаляється через один попап, «+Додати довідник») і **«Системні»** (5 пунктів: Виробники, Постачальники, Країни, Валюти, Одиниці виміру — без можливості видалити весь довідник).

## Використовує з ui-kit

## Дані
«Категорії товару» — таблиця `categories` у PostgreSQL (повний CRUD через `server/data/categories.ts` + Server Actions), тенант-скоуповано, RLS. `products.category_id` (FK на `categories.id`, `ON DELETE SET NULL`) — реальний зв'язок товару з категорією, звідки рахується «Товарів» у списку. Довідники — статичний масив у `ReferencesList.tsx` (5 «Системні», `group`-поле) + 4 плитки поза масивом («Кольори»/«Тип тканини та матеріал»/«Інструкція по догляду»/«Розміри та заміри», кожна плитка+попап без окремої сторінки) + довільна кількість `custom_characteristics`; усі — з реальною БД, тенант-скоуповано, RLS: «Кольори» (`colors`), «Валюти» (`currencies`), «Постачальники» (`suppliers`+3 дочірні), «Характеристики» (`custom_characteristics`+`custom_characteristic_values`), «Прапорці довідників поза custom_characteristics» (`reference_dictionary_flags`), «Тип тканини та матеріал» (`fabric_types`+`fabric_type_possible_materials`+`materials`), «Інструкція по догляду» (`care_instructions`), «Розміри та заміри» (`size_types`+`size_values`, `measurement_types`+`measurement_values` — два незалежні довідники в одному попапі) — `page.tsx` тягне всі ці списки й пробрасовує пропами в `ReferencesList` для лічильника й прев'ю значень. Деталі схеми — `db.md`.
«Тип тканини та матеріал» — **без власної сторінки** (за прямою вказівкою людини, `decisions.md`): плитка `FabricTypesTile` у гріді «Довідники» показує наявні типи чіпами, кожен чіп і «+Додати» відкривають `FabricTypeFormDialog` (основна інформація + «Можливі матеріали»); довідник «Матеріали» керується вбудованою секцією `MaterialsManager` усередині того самого попапу, теж без окремої сторінки.
Картка товару (`/products/[id]`) тепер читає `listColors(tenantId)` і пробрасовує в `ProductGeneralTab` → `ProductInfoPanel` (поле «Колір» без варіацій) та `ProductSkuSection` → `ProductSkuTable` (конструктор SKU-матриці, дропдаун «+Колір») — раніше обидва брали хардкод `COLOR_OPTIONS` з `lib/constants/sku-variant-options.ts` (тепер видалено, лишився тільки тип `ColorOption`).
Теги товару (`ProductMetaPanel` → `TagsSection`) — і далі та сама таблиця `product_tags`, лише `characteristic_value_id` замість колишнього `tag_id`; `syncProductTags` (`server/data/products.ts`) знаходить/створює характеристику «Теги» тенанта за `system_key="tags"` (не за назвою). UI картки товару не змінився — лише джерело в БД, `db.md`.

**Нюанс Select з ui-kit:** якщо `value` опції не збігається з людським лейблом (напр. `"all"`/`"active"`, а не сам текст), `SelectValue` треба явно дати render-функцію (`<SelectValue>{(value) => label}</SelectValue>`) — інакше показує сирий `value`. У `CategorySelectRow` (`ProductInfoPanel`) цього не було видно, бо там `value` і лейбл — той самий рядок.
